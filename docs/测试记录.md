## 2.5 并发预约测试（6 线程抢同一时段）

执行：

```bash
python scripts/concurrency_test.py 6
```

测试目标：`court=1，2026-11-21 08:00-09:00`，6 个线程使用不同 `requestId` 同时下单。

最终结果：

```
测试目标: court=1 2026-11-21 08:00:00 ~ 2026-11-21 09:00:00, 并发线程=6
成功: 1  冲突: 5  其他: 0
  HTTP 200 bookingId=13 预约成功
  HTTP 409 bookingId=None 预约失败：所选时间段已被占用，请刷新后重试
  HTTP 409 bookingId=None 预约失败：所选时间段已被占用，请刷新后重试
  HTTP 409 bookingId=None 预约失败：所选时间段已被占用，请刷新后重试
  HTTP 409 bookingId=None 预约失败：所选时间段已被占用，请刷新后重试
  HTTP 409 bookingId=None 预约失败：所选时间段已被占用，请刷新后重试
RESULT: PASS
```

**首轮发现的问题与修复：**

首轮 6 线程测试结果为「1 成功、2 冲突、3 个 HTTP 500」，错误为：

```
MySQLTransactionRollbackException: Deadlock found when trying to get lock
SQL: INSERT IGNORE INTO court_slot ...（一次性插入整日 31 个时间段）
```

原因：每个预约事务都会对整日时间段执行 `INSERT IGNORE`，即使记录已存在也会申请重复键检查锁；与随后 `SELECT ... FOR UPDATE` 的排他锁交叉，形成死锁。

修复：

1. `BookingService` 先 `countRange` 统计区间内已存在的时间段，只有数量不足时才补齐，而且只补预约区间内的 4 段，不再整日插入。
2. 增加 `CourtService.ensureSlotsRange`，精确补齐区间。
3. 对 `DeadlockLoserDataAccessException / CannotAcquireLockException` 统一映射为 `409 当前时段预约人数较多，请稍后重试`，不再返回 500。

复测结果：**1 成功、5 冲突、0 个 500，PASS**。

C 端验收中发现并修复的问题：

1. **刷新后会员态丢失**：公开页 `/club/home`、`/club/booking` 的路由守卫直接放行，Pinia 只有 localStorage token、没有 user，导致导航显示未登录、折扣按原价预览（后端仍按会员价成交）。修复为公开页也执行 `fetchMe()` 恢复用户。
2. **吉祥物不显示**：`<img loading="lazy">` 在绝对定位、零高度容器中未触发加载，`naturalWidth=0`。移除懒加载并改用 `object-fit: contain`，角色正常显示。
3. **手机端横向溢出**：日期条内容把 `.filter-card` 撑到 1126px。为 grid 子项与 flex 滚动容器补 `min-width: 0`、`overflow` 约束，390px 下无横向滚动。
4. **预约页默认时间过期**：默认整点 10:00 在业务时间 10:20 时提交会报「不能预约过去的时间段」。改为按服务端时间向上取整到下一个 30 分钟，接近闭馆自动跳次日。
5. **暗色输入框残留**：C 端浅色页面复用了后台暗色 input 样式，日期筛选显示为灰块。增加 C 端 Element Plus 输入/按钮/抽屉/日历覆盖。
6. **禁用按钮仍高亮**：`c-btn-primary` 未定义 disabled 样式，确认按钮在未选场地时看起来可点。补充禁用态。
7. **调级弹窗默认当前等级**：后台调级弹窗默认选中当前等级，提交必然报「已是该等级」。改为默认不选。
8. **预约操作列裁切**：后台预约表格操作列宽度不足，「未到场」按钮被裁切。加宽到 330px。

## 5. 已知限制（如实说明）

1. **支付为演示实现**：创建预约即视为支付成功（`payNow=true`），未接入微信/支付宝网关；`PENDING_PAYMENT` 订单支付前不占场，存在支付时被他人抢占的可能，这是有意的业务取舍。
2. **不支持跨午夜预约**：场馆营业时间 08:00-23:30，预约必须在同一天内结束；跨自然日统计针对的是实际使用超时（如 22:30 用到次日 00:30），测试十已覆盖。
3. **完成订单保留时间段 BOOKED**：历史占用不会被释放，用于回看；若通过模拟时钟跳到未来日期再完成使用，该未来日期的段会显示已占用，这是时间旅行演示的边界情况。
4. **退款未建模**：取消已支付订单只改状态，没有退款流水；生产系统应增加退款单与支付流水表。
5. **模拟时钟轮询**：前端每 8 秒拉取一次，不是 WebSocket 推送；秒级显示由接口返回值驱动，不做本地插值。
6. **前端响应式**：C 端已适配 390px 手机并验证无横向溢出；后台管理端按桌面 1280px 以上设计，900px 以下隐藏侧边栏，未做移动端完整适配。
7. **操作日志为 AOP 同步写入**：写日志失败只记录警告，不影响主业务；生产环境建议改为消息队列异步落库。
8. **C 端不支持修改资料/头像**：后端未开放 C 端资料编辑接口，个人中心只读展示会员资料；等级由管理员在后台调整。
9. **C 端可预约窗口为 30 天**：日期条展示 14 天，更多日期通过日历选择；超出 30 天不可预约。
10. **C 端未接入真实支付**：确认即支付成功，属于课程演示实现。
