# 部署与启动说明

## 1. 运行环境

本项目在以下环境完成开发与真实启动验证：

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 11 | 项目路径 `C:\Users\蟹黄堡\WorkBuddy\数据库` |
| MySQL | 8.0.28（Windows x64 ZIP） | 端口 **3307**，数据目录 `D:\DevTools\badminton-runtime\mysql-data` |

> 在其他机器部署时，安装同版本组件并修改 `scripts/env.bat` 与 `backend/src/main/resources/application.yml` 即可。

## 3. 端口与配置

| 服务 | 端口 | 配置位置 |
| --- | --- | --- |
| MySQL | 3307 | `D:\DevTools\badminton-runtime\my.ini` |
| Spring Boot | 8080 | `backend/src/main/resources/application.yml` |
| Vite Dev Server | 5173 | `frontend/vite.config.ts` |

数据库连接（`application.yml`）：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3307/badminton_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: root
    password: root123
```

如修改端口/密码，同步修改 `scripts/env.bat` 中的 `MYSQL_PORT / MYSQL_PWD`。

前端接口地址（`frontend/.env.development`）：

```bash
# 默认通过 Vite 代理访问 8080
VITE_API_BASE_URL=/api
```

若前后端不同源，可复制 `frontend/.env.example` 为 `.env.local`：

```bash
VITE_API_BASE_URL=http://127.0.0.1:8080/api
```

此时需确认后端 `app.cors.allowed-origins` 包含前端地址。

## 4. 首次部署（全新机器）

### 4.1 准备运行时

1. 安装 JDK 17，配置 `JAVA_HOME`。
2. 安装 Maven 3.9+。
3. 下载 MySQL 8.0 ZIP 并解压，例如 `D:\DevTools\badminton-runtime\mysql\mysql-8.0.28-winx64`。
4. 安装 Node.js 18+。

修改 `scripts/env.bat`：

```bat
set "RUNTIME_HOME=D:\DevTools\badminton-runtime"
set "JAVA_HOME=%RUNTIME_HOME%\jdk17\jdk-17.0.21+9"
set "MAVEN_HOME=%RUNTIME_HOME%\maven\apache-maven-3.9.16"
set "MYSQL_HOME=%RUNTIME_HOME%\mysql\mysql-8.0.28-winx64"
set "MYSQL_PORT=3307"
set "MYSQL_PWD=root123"
```

同时把 `scripts\my.ini.example` 复制为 `%RUNTIME_HOME%\my.ini`，并把 `basedir / datadir / log-error` 改成实际路径。当前开发机的 `my.ini` 已位于 `D:\DevTools\badminton-runtime\my.ini`。

### 4.2 初始化 MySQL

```bat
scripts\init-mysql.bat
```

脚本会：

1. 用 `--initialize-insecure` 初始化数据目录；
2. 启动 `mysqld`（3307）；
3. 将 root 密码设置为 `root123`。

若数据目录已存在，脚本会跳过初始化。

### 4.3 建库并导入演示数据

```bat
scripts\init-db.bat
```

按顺序执行：

```
01_create_database.sql
02_create_tables.sql
03_create_indexes.sql
04_create_triggers.sql
05_create_views.sql
06_create_procedures.sql
07_seed_data.sql
```

该脚本会 **DROP 并重建** `badminton_db`，可随时用于恢复演示数据。

### 4.4 启动后端

```bat
scripts\start-backend.bat
```

首次会自动执行：

```bat
mvn -s scripts\maven-settings.xml -DskipTests package
java -jar backend\target\badminton-admin-1.0.0.jar
```

启动成功后：

- API：<http://127.0.0.1:8080/api>
- Swagger：<http://127.0.0.1:8080/swagger-ui.html>

### 4.5 启动前端

```bat
scripts\start-frontend.bat
```

首次自动 `npm install`（已配置 npmmirror），然后启动 Vite：

- C 端首页：<http://127.0.0.1:5173/>
- C 端登录/注册：<http://127.0.0.1:5173/club/login>
- C 端场地预约：<http://127.0.0.1:5173/club/booking>
- 管理端：<http://127.0.0.1:5173/login>

### 4.6 一键启动

```bat
scripts\start-all.bat
```

依次打开 MySQL、后端、前端三个窗口。首次仍需先执行 `init-mysql.bat` 与 `init-db.bat`。

## 5. 手动启动（不使用批处理）

```bash
# 1. MySQL
"D:/DevTools/badminton-runtime/mysql/mysql-8.0.28-winx64/bin/mysqld.exe" \
  --defaults-file="D:/DevTools/badminton-runtime/my.ini" --console

# 2. 后端
export JAVA_HOME="D:/DevTools/badminton-runtime/jdk17/jdk-17.0.21+9"
cd backend
"D:/DevTools/badminton-runtime/maven/apache-maven-3.9.16/bin/mvn" \
  -s ../scripts/maven-settings.xml -DskipTests package
"$JAVA_HOME/bin/java" -jar target/badminton-admin-1.0.0.jar

# 3. 前端
cd frontend
npm install
npm run dev
```

## 11. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端启动报 `Communications link failure` | MySQL 未启动或端口不是 3307；执行 `start-mysql.bat` 并检查 `my.ini` |
| `Access denied for user 'root'` | 密码不是 `root123`；修改 `application.yml` 或重新执行 `init-mysql.bat` |
| 前端 401 并跳回登录页 | Token 过期（12 小时）或后端重启后密钥变化；重新登录 |
| 预约提示“时间段已被占用” | 该场地该时段已有有效预约；刷新日历选择其他时段 |
| 预约提示“尚未初始化” | 时间段未生成；在场地管理点击“生成时间段” |
| 页面无数据 | 后端未启动或数据库被清空；检查 8080 端口与 `init-db.bat` |
| npm 安装慢 | `.npmrc` 已配置 npmmirror；仍慢可设置代理 |
| 修改了场地单价，历史订单金额变了？ | 不会。预约保存 `hourly_rate_snapshot` 与 `discount_snapshot` |

## 12. 生产环境注意事项

当前配置面向课程演示，生产部署需额外处理：

1. 修改 `app.jwt.secret`，使用环境变量或配置中心，不要提交到仓库。
2. 数据库账号最小权限，禁止使用 root。
3. 关闭 Swagger 或加访问控制。
4. 前端使用 `npm run build` 产物，由 Nginx 托管并反向代理 `/api`。
5. 开启 HTTPS，配置 CORS 白名单。
6. 支付环节接入真实支付网关，当前为演示用即时支付。
7. 增加数据库备份、慢查询监控与日志轮转。
